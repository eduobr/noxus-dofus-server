### Fase 2: Instalar MongoDB con Docker (a cargo del usuario)

**Objetivo**: Tener una instancia MongoDB 3.6 accesible en localhost:27017.

**Pre-requisito único**: Arreglar Docker (el daemon está inactive/dead y el
socket no existe):

```bash
sudo usermod -aG docker $USER    # Agregarse al grupo (requiere re-login)
sudo systemctl enable docker --now  # Habilitar e iniciar el daemon
```

Luego:

```bash
docker run -d \
  --name noxus-mongo \
  -p 27017:27017 \
  -v noxus-mongo-data:/data/db \
  mongo:3.6
```

Verificar:

```bash
docker exec noxus-mongo mongo --eval "db.runCommand({ping:1})"
```

**Alternativa si mongo:3.6 falla**: Usar `mongo:4.0`. El driver 2.2.x funciona
con MongoDB hasta 4.2 en modo compatibilidad.

---

### Fase 3: Instalar dependencias npm

**Objetivo**: Instalar todas las dependencias listadas en package.json.

1. Con Node 12 activo:
   ```bash
   npm install
   ```

2. Verificar que las dependencias clave existen:
   ```bash
   ls node_modules/babel-cli
   ls node_modules/mongodb
   ```

**Riesgos y mitigaciones**:

| Riesgo | Mitigación |
|--------|------------|
| `babel-cli` falla al compilar en Node 12 | Probar con `--ignore-scripts` o bajar a Node 8 |
| `mongodb` driver 2.2.x falla al compilar módulos nativos (kerberos, bson) | Instalar con `npm install --build-from-source` o usar flag `--no-optional` |
| `node-gyp` no encuentra Python/build tools | `pacman -S python2 make gcc` (Arch Linux). En Arch moderno, python2 puede no estar → usar python3 con `npm config set python python3` |
| Errores de peer dependencies | `npm install --legacy-peer-deps` |

### Fase 4: Importar datos de juego a MongoDB

**Objetivo**: Poblar la base de datos `Noxus` con los 28 JSON de la carpeta `db/`.

1. Crear script de importación o usar `mongoimport` dentro del contenedor:

   ```bash
   for f in db/*.json; do
     collection=$(basename "$f" .json)
     docker exec -i noxus-mongo mongoimport \
       --db Noxus --collection "$collection" \
       --file - < "$f"
   done
   ```

2. Verificar que las colecciones se crearon:
   ```bash
   docker exec noxus-mongo mongo Noxus --eval "db.getCollectionNames()"
   ```

**Nota**: La colección `Npcs.json` tiene mayúscula (las demás son minúsculas).
En MongoDB los nombres de colección son case-sensitive. Verificar que el código
usa exactamente el mismo casing.

**Riesgo**: Algunos JSONs pueden tener formato incorrecto (no array) o campos
que violen restricciones de MongoDB 3.6. Procesar uno por uno y reportar fallos.

**Tiempo estimado**: 2-5 minutos para los 166MB.

### Fase 5: Compilar con Babel

**Objetivo**: Transpilar ES6/ES2015 → ES5 en `dist/`.

1. Ejecutar compilación:
   ```bash
   ./node_modules/.bin/babel src --out-dir dist
   ```

2. Verificar que `dist/app.js` existe y es código ES5 válido.

**Riesgo**: Errores de sintaxis en archivos fuente que Babel no puede parsear.
En ese caso, revisar archivo por archivo. Los más problemáticos:
- `bytearray.js` y `custom_data_wrapper.js` (código pre-ES6 con prototipos)
- Archivos con `require()` dinámico (fight_spell_processor.js línea 18-19)

Si hay archivos problemáticos, copiarlos tal cual a `dist/` sin transpilar
(son compatibles con Node 12 de todas formas).
