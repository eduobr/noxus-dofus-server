# Plan: Migrar Noxus de MongoDB 4.2 a MongoDB 8.0

**Fecha**: 2026-05-14
**Objetivo**: Migrar la base de datos local de Noxus desde el contenedor Docker `mongo:4.2` (`noxus-mongo`) a MongoDB 8.0, preservando los datos actuales (`Noxus`, cuenta `test:test`, personaje `Bizelzapobany`) y manteniendo el servidor Node 25 funcional sin cambiar `config.json`.

**Resultado de ejecución**: completado en la rama `migration/mongodb8`. MongoDB 8.0.23 quedó operativo en `noxus-mongo8` con volumen `noxus-mongo8-data`; `noxus-mongo` (`mongo:4.2`) quedó detenido como rollback con volumen `noxus-mongo-data-42`; `config.json` no se modificó; `client-test.js` llegó a `🎉 ¡CONTEXTO DE JUEGO CREADO!`; documentación y `.gitignore` quedaron commiteados en `f47c02a`.

### Fase 2: Detener servidor Noxus y asegurar MongoDB 4.2 activo

**Objetivo**: Evitar escrituras concurrentes mientras se hace el dump y confirmar que MongoDB 4.2 responde.

**Estado**: Ejecutada.

**Comandos exactos**:

```bash
cd /home/enoh/Documentos/mis-proyectos/Dofus
```

### Fase 3: Crear backup lógico con `mongodump` desde MongoDB 4.2

**Objetivo**: Exportar la DB `Noxus` a un backup portable, independiente del formato de archivos de MongoDB 4.2.

**Estado**: Ejecutada.

**Comandos exactos**:

```bash
cd /home/enoh/Documentos/mis-proyectos/Dofus
export DOCKER_HOST=unix:///home/enoh/.docker/desktop/docker.sock

mkdir -p backups/mongodb
rm -rf backups/mongodb/noxus-4.2-before-mongo8

docker exec noxus-mongo mongodump --db Noxus --out /tmp/noxus-4.2-before-mongo8

docker cp noxus-mongo:/tmp/noxus-4.2-before-mongo8 backups/mongodb/noxus-4.2-before-mongo8

test -d backups/mongodb/noxus-4.2-before-mongo8/Noxus
```

**Riesgos específicos**:
- No usar el volumen `noxus-mongo-data-42` directamente con MongoDB 8.0: no es una ruta de upgrade segura desde 4.2.
- El backup contiene datos de cuentas/personajes. No subirlo a Git si contiene información sensible. Revisar `.gitignore` antes de commitear.

### Fase 4: Crear contenedor MongoDB 8.0 separado

**Objetivo**: Levantar MongoDB 8.0 en un contenedor nuevo (`noxus-mongo8`) con volumen nuevo, sin destruir el contenedor 4.2.

**Estado**: Ejecutada.

**Comandos exactos**:

```bash
cd /home/enoh/Documentos/mis-proyectos/Dofus
export DOCKER_HOST=unix:///home/enoh/.docker/desktop/docker.sock

# Liberar el puerto 27017: solo puede estar activo un MongoDB local a la vez.
docker stop noxus-mongo

# Si existía un intento anterior de Mongo 8, eliminar solo el contenedor, no el volumen.
docker rm noxus-mongo8 2>/dev/null || true

docker volume create noxus-mongo8-data

docker run -d \
  --name noxus-mongo8 \
  -p 27017:27017 \
  -v noxus-mongo8-data:/data/db \
  mongo:8.0

# Esperar a que MongoDB responda.
for i in $(seq 1 30); do
  if docker exec noxus-mongo8 mongosh --quiet --eval 'db.adminCommand({ ping: 1 }).ok' | grep -q '^1$'; then
    echo 'MongoDB 8.0 listo'
    break
  fi
  sleep 1
done

docker exec noxus-mongo8 mongosh --quiet --eval 'db.version()'
```

**Riesgos específicos**:
- La imagen `mongo:8.0` usa `mongosh`, no `mongo`.
- Si el puerto 27017 queda ocupado, revisar procesos/containers antes de continuar.
- No eliminar `noxus-mongo` ni `noxus-mongo-data-42` hasta validar el rollback.

### Fase 5: Restaurar backup en MongoDB 8.0

**Objetivo**: Importar la base `Noxus` del dump 4.2 en el contenedor MongoDB 8.0.

**Estado**: Ejecutada.

**Comandos exactos**:

```bash
cd /home/enoh/Documentos/mis-proyectos/Dofus
export DOCKER_HOST=unix:///home/enoh/.docker/desktop/docker.sock

docker cp backups/mongodb/noxus-4.2-before-mongo8 noxus-mongo8:/tmp/noxus-4.2-before-mongo8

docker exec noxus-mongo8 mongorestore --drop --db Noxus /tmp/noxus-4.2-before-mongo8/Noxus

docker exec noxus-mongo8 mongosh --quiet Noxus --eval 'printjson({accounts: db.accounts.countDocuments(), characters: db.characters.countDocuments(), heads: db.heads.countDocuments(), maps: db.maps.countDocuments()})'
docker exec noxus-mongo8 mongosh --quiet Noxus --eval 'printjson(db.accounts.findOne({username:"test"}))'
docker exec noxus-mongo8 mongosh --quiet Noxus --eval 'printjson(db.characters.findOne({_id:27}))'
```

**Riesgos específicos**:
- `mongorestore --drop` borra primero las colecciones destino en MongoDB 8.0; solo usarlo contra `noxus-mongo8`, nunca contra el contenedor viejo por accidente.
- Verificar explícitamente el nombre del contenedor en cada comando antes de ejecutar.

### Fase 6: Validar servidor Noxus contra MongoDB 8.0

**Objetivo**: Confirmar que el driver `mongodb@6.3.0`, `DBManager` y `Datacenter` funcionan contra MongoDB 8.0.

**Estado**: Ejecutada.

**Comandos exactos**:

```bash
cd /home/enoh/Documentos/mis-proyectos/Dofus
export PATH="/home/enoh/.nvm/versions/node/v25.3.0/bin:$PATH"
export DOCKER_HOST=unix:///home/enoh/.docker/desktop/docker.sock

pkill -9 -f 'node src/app.js' 2>/dev/null || true
fuser -k 443/tcp 5556/tcp 2>/dev/null || true

node src/app.js > /tmp/noxus-mongo8.log 2>&1 &

for i in $(seq 1 30); do
  if ss -tlnp | grep -qE '127\.0\.0\.1:(443|5556)\b'; then
    ss -tlnp | grep -E ':(443|5556)\b'
    break
  fi
  sleep 1
done

# Inspeccionar errores de arranque.
grep -E 'Connected to MongoDB|Loaded|Auth server started|World server started|Server started successfully|Mongo|ERROR|Error|MongoServerError|MongoCompatibilityError' /tmp/noxus-mongo8.log | tail -80

# Validación funcional completa. El timeout final conocido del cliente no es fallo si aparece el banner de éxito.
set +e
node client-test.js > /tmp/noxus-client-mongo8.log 2>&1
code=$?
cat /tmp/noxus-client-mongo8.log
if grep -q 'CONTEXTO DE JUEGO CREADO' /tmp/noxus-client-mongo8.log; then
  echo 'VALIDATION_OK: GameContextCreateMessage alcanzado con MongoDB 8.0'
  exit 0
fi
exit $code
```

**Riesgos específicos**:
- Si falla por query o write concern, revisar `src/database/dbmanager.js` primero.
- Si falla al cargar datos estáticos, comparar conteos de colecciones entre 4.2 y 8.0.
- Si el flujo llega a selección pero falla en look/head, validar `db.heads.countDocuments()` y `cosmeticId` del personaje.

## Riesgos y plan B

| Riesgo | Probabilidad | Mitigación / plan B |
|---|---:|---|
| Intentar usar el volumen de MongoDB 4.2 directamente en MongoDB 8.0 corrompe o no arranca | Alta | No hacer in-place. Usar `mongodump` desde 4.2 y `mongorestore` en 8.0 con volumen nuevo |
| Backups con datos reales quedan versionados por accidente | Media | Agregar `backups/` a `.gitignore` antes del commit; revisar `git status --short` |
| `mongorestore` cambia tipos o índices de forma incompatible | Media | Validar conteos, documentos clave (`test`, personaje `_id:27`) y flujo `client-test.js` |
| Driver `mongodb@6.3.0` presenta warnings/errores con MongoDB 8.0 | Baja-Media | Actualizar `mongodb` a una versión 6.x más reciente solo si hay error concreto; validar con `pnpm install` y `client-test.js` |
| Puerto `27017` ocupado por el contenedor viejo | Media | Detener explícitamente `noxus-mongo` antes de iniciar `noxus-mongo8` |
| Pérdida accidental del entorno MongoDB 4.2 | Baja si se sigue el plan | No eliminar `noxus-mongo` ni `noxus-mongo-data-42`; rollback con `docker stop noxus-mongo8 && docker start noxus-mongo` |
| Diferencias de shell: `mongo` vs `mongosh` | Alta | Usar `mongo` solo en `noxus-mongo` 4.2; usar `mongosh` en `noxus-mongo8` |
| El cliente de prueba termina con timeout aunque el flujo haya pasado | Alta / conocido | Considerar éxito si aparece `🎉 ¡CONTEXTO DE JUEGO CREADO!` o `GameContextCreateMessage` |
